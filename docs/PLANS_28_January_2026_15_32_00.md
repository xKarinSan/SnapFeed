# Implementation Plan: Enhanced Export with Screenshots

## Overview

Enhance the markdown export feature to produce a structured report with:
1. **Project Name** - Title and metadata
2. **General Notes** - Existing non-UI feedback items
3. **Screenshots + Notes** - All project screenshots with their annotations, embedded as base64 images

The export will be fully self-contained (no external dependencies) by embedding screenshots directly in the markdown.

## Tech Stack

| Layer | Technology | Rationale |
|-------|------------|-----------|
| Export Logic | TypeScript | Existing codebase pattern |
| Image Processing | Node.js `fs` module | Read screenshot files and convert to base64 |
| Data Access | Prisma | Existing ORM, use `getScreenshotsByProject` |
| API | Next.js App Router | Existing export route pattern |

## Features

### 1. Enhanced Markdown Export Structure
- **Description**: Reorganize export output to follow the user's desired structure
- **Key files**: `src/lib/export/markdown.ts`
- **Dependencies**: None

### 2. Screenshot Embedding
- **Description**: Read screenshot files from disk and embed as base64 data URLs
- **Key files**: `src/lib/export/markdown.ts`, `src/app/api/projects/[id]/export/route.ts`
- **Dependencies**: Feature 1

### 3. Annotation Rendering
- **Description**: Include screenshot annotations (notes) with each screenshot
- **Key files**: `src/lib/export/markdown.ts`
- **Dependencies**: Feature 2

## Data Schema

No schema changes required. Using existing models:

```
Project (id, name, url)
    └── Feedback (type: "non-ui") → "General Notes"
    └── Screenshot (filename, pageTitle, pageUrl)
            └── Annotation (content, author, posX, posY) → "Screenshot Notes"
```

## Implementation Steps

### Phase 1: Update Export Data Interface

**Step 1.1**: Modify `ExportData` interface in `markdown.ts`
- Add `screenshots` array with annotations
- Add type definitions for Screenshot and Annotation

**Files to modify**:
- `src/lib/export/markdown.ts`

### Phase 2: Update Export Route

**Step 2.1**: Fetch screenshots with annotations in export route
- Import `getScreenshotsByProject` from db utilities
- Include screenshots data in export call

**Step 2.2**: Read screenshot files and convert to base64
- Read each screenshot file from `uploads/screenshots/`
- Convert to base64 data URL format

**Files to modify**:
- `src/app/api/projects/[id]/export/route.ts`

### Phase 3: Restructure Markdown Output

**Step 3.1**: Reorder sections in `generateMarkdownExport`
1. Project Name (title + metadata)
2. General Notes (non-UI feedback)
3. Screenshots section

**Step 3.2**: Implement screenshot section generator
- For each screenshot:
  - Display title/page URL
  - Embed base64 image
  - List all annotations with author and position

**Step 3.3**: Remove or relocate UI feedback section
- Move UI feedback to after screenshots OR remove if not needed

**Files to modify**:
- `src/lib/export/markdown.ts`

## Expected Output Format

```markdown
# Feedback Report: {Project Name}

**URL**: {project url}
**Exported**: {date}

---

## General Notes

### 1. "{content}" — {author}
- **Status**: Open/Resolved

---

## Screenshots

### Screenshot 1: {pageTitle or pageUrl}

![Screenshot]({base64 data URL})

**Annotations:**
1. "{content}" — {author} (at {posX}%, {posY}%)
2. ...

---

### Screenshot 2: ...
```

## Considerations

### Performance
- Base64 encoding increases file size ~33%
- Large screenshots may create very large markdown files
- Consider adding a file size warning for exports with many screenshots

### Security
- Screenshot paths are already sanitized in existing code
- Base64 encoding eliminates path traversal risks in exported files

### Testing Approach
1. Test export with project containing:
   - Multiple non-UI feedback items
   - Multiple screenshots
   - Screenshots with and without annotations
2. Verify markdown renders correctly in common viewers (VS Code, GitHub)
3. Verify base64 images display in markdown preview

### Edge Cases
- Projects with no screenshots → Skip screenshots section
- Projects with no general notes → Skip general notes section
- Screenshots without annotations → Show image only, skip annotations list
- Missing screenshot files → Log warning, skip that screenshot
