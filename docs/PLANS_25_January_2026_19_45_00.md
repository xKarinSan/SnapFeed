# Implementation Plan: Enhanced Mini Browser with Screenshots & Annotations

## Overview

Transform the current iframe-based website viewer into a fully navigable "mini browser" powered by a server-side headless browser (Puppeteer). Users can browse websites freely, capture timestamped screenshots, and add positional annotations to specific parts of each screenshot.

**Key Insight**: Cross-origin iframes cannot be captured or controlled programmatically. To enable full navigation and screenshots, we'll use Puppeteer on the server to render websites and stream the viewport to clients.

---

## Tech Stack Additions

| Layer | Technology | Rationale |
|-------|------------|-----------|
| Server Browser | Puppeteer | Headless Chrome for rendering, navigation, and native screenshots |
| Image Storage | Local filesystem (`/uploads/screenshots`) | Simple, works with SQLite, Docker volume-mountable |
| Real-time Control | Socket.io (existing) | Stream viewport updates and handle user interactions |
| Image Serving | Next.js static file serving | Serve screenshots via `/api/screenshots/[filename]` |

## Features

### Feature 1: Mini Browser with Full Navigation
**Description**: Replace iframe with a server-rendered browser viewport that supports clicking links, submitting forms, and full navigation.

**Key Components/Files**:
- `src/components/MiniBrowser.tsx` - Main browser UI component
- `src/components/BrowserToolbar.tsx` - URL bar, back/forward/refresh buttons
- `src/components/BrowserViewport.tsx` - Displays rendered page image
- `src/lib/browser/BrowserSessionManager.ts` - Manages Puppeteer instances per user
- `src/lib/socket/browserEvents.ts` - Socket.io events for browser control
- `server.ts` - Extended to handle browser sessions

**User Flow**:
1. User enters URL in the toolbar
2. Server creates/reuses Puppeteer browser session
3. Server navigates to URL, captures viewport
4. Viewport image streamed to client via Socket.io
5. User clicks on viewport → coordinates sent to server → Puppeteer clicks → new viewport returned
6. Scroll, type, form submit all handled similarly

**Dependencies**: None (foundational feature)

---

### Feature 2: Timestamped Screenshots
**Description**: Users can capture the current browser viewport as a timestamped screenshot, stored on the server filesystem.

**Key Components/Files**:
- `src/components/ScreenshotButton.tsx` - Capture button in toolbar
- `src/components/ScreenshotGallery.tsx` - Grid view of captured screenshots
- `src/components/ScreenshotThumbnail.tsx` - Individual screenshot preview
- `src/lib/db/screenshots.ts` - Database operations for screenshots
- `src/app/api/projects/[id]/screenshots/route.ts` - GET/POST screenshots
- `src/app/api/screenshots/[filename]/route.ts` - Serve screenshot images
- `prisma/schema.prisma` - Add Screenshot model

**User Flow**:
1. User clicks "Capture Screenshot" button
2. Server takes Puppeteer screenshot, saves to `/uploads/screenshots/`
3. Screenshot metadata (timestamp, URL, filename) saved to database
4. Thumbnail appears in screenshot gallery
5. User can click thumbnail to view/annotate

**Dependencies**: Feature 1 (Mini Browser)

---

### Feature 3: Screenshot Annotations
**Description**: Users can add positional notes to specific parts of a screenshot, similar to the existing feedback pin system but on static images.

**Key Components/Files**:
- `src/components/ScreenshotViewer.tsx` - Full-screen screenshot with annotation layer
- `src/components/AnnotationCanvas.tsx` - Overlay for placing annotation pins
- `src/components/AnnotationPin.tsx` - Visual marker on screenshot
- `src/components/AnnotationForm.tsx` - Form for adding annotation content
- `src/components/AnnotationList.tsx` - Sidebar list of all annotations
- `src/lib/db/annotations.ts` - Database operations for annotations
- `src/app/api/screenshots/[id]/annotations/route.ts` - CRUD for annotations
- `prisma/schema.prisma` - Add Annotation model

**User Flow**:
1. User opens a screenshot from the gallery
2. Screenshot displays full-screen with transparent overlay
3. User clicks on a spot → annotation form opens
4. User enters note content → annotation saved with x/y coordinates
5. Numbered pins appear on screenshot at annotation positions
6. Sidebar shows all annotations with ability to edit/delete

**Dependencies**: Feature 2 (Screenshots)

## Data Schema

### New Models (Prisma)

```prisma
model Screenshot {
  id          String       @id @default(uuid())
  projectId   String
  project     Project      @relation(fields: [projectId], references: [id], onDelete: Cascade)
  sessionId   String       // User session who took the screenshot
  filename    String       @unique
  pageUrl     String       // URL at time of capture
  pageTitle   String?      // Page title at time of capture
  createdAt   DateTime     @default(now())
  annotations Annotation[]
}

model Annotation {
  id           String     @id @default(uuid())
  screenshotId String
  screenshot   Screenshot @relation(fields: [screenshotId], references: [id], onDelete: Cascade)
  content      String
  author       String
  posX         Float      // Percentage (0-100) from left
  posY         Float      // Percentage (0-100) from top
  createdAt    DateTime   @default(now())
  updatedAt    DateTime   @updatedAt
}
```

### Updated Project Model

```prisma
model Project {
  // ... existing fields
  screenshots Screenshot[]
}
```

## Implementation Steps

### Phase 1: Server-Side Browser Infrastructure

1. **Install Puppeteer dependency**
   - Add `puppeteer` to package.json
   - Configure for Docker deployment (chromium installation)

2. **Create BrowserSessionManager**
   - File: `src/lib/browser/BrowserSessionManager.ts`
   - Singleton class managing Puppeteer browser instances
   - Map of sessionId → { browser, page, lastActivity }
   - Auto-cleanup of idle sessions (timeout after 10 minutes)
   - Methods: `createSession()`, `navigateTo()`, `click()`, `scroll()`, `type()`, `getViewport()`, `destroySession()`

3. **Extend Socket.io server for browser events**
   - File: `src/lib/socket/browserEvents.ts`
   - Events: `browser:navigate`, `browser:click`, `browser:scroll`, `browser:type`, `browser:viewport`
   - File: `server.ts` - integrate browser event handlers

4. **Update Dockerfile for Puppeteer**
   - Install Chromium dependencies
   - Set appropriate environment variables

### Phase 2: Mini Browser UI

5. **Create BrowserToolbar component**
   - File: `src/components/BrowserToolbar.tsx`
   - URL input field with submit
   - Back, forward, refresh buttons
   - Loading indicator
   - Screenshot capture button

6. **Create BrowserViewport component**
   - File: `src/components/BrowserViewport.tsx`
   - Displays server-rendered viewport as image

   - Handles scroll events → sends to server

7. **Create MiniBrowser container component**
   - File: `src/components/MiniBrowser.tsx`

8. **Create useBrowserSession hook**
   - File: `src/hooks/useBrowserSession.ts`
   - Manages Socket.io subscription for browser events

9. **Update project detail page**

## Considerations

### Security
- **Puppeteer sandboxing**: Run with `--no-sandbox` in Docker but ensure container isolation
- **URL validation**: Prevent navigation to internal/localhost URLs
- **Resource limits**: Cap concurrent browser sessions per server
- **Session timeout**: Auto-destroy idle browser sessions

### Performance
- **Viewport streaming**: Send compressed JPEGs (quality: 80) instead of PNGs
- **Debounce interactions**: Throttle scroll/mouse events (100ms)
- **Session pooling**: Reuse browser instances, only create new pages
- **Image optimization**: Generate thumbnails for gallery view
- **Memory management**: Monitor and limit Puppeteer memory usage

### Docker Deployment
- Use `puppeteer` with bundled Chromium or install system Chromium
- Add required dependencies: `libx11`, `libxcomposite`, `libxdamage`, etc.
- Increase shared memory: `--shm-size=1gb`
- Mount volume for `/uploads` persistence

### Testing Approach
- Unit tests for BrowserSessionManager
- Integration tests for screenshot API routes
- E2E tests for browser navigation flow
- Manual testing with various websites (SPAs, static, blocked sites)

### Limitations & Workarounds
- **Some sites block headless browsers**: Use stealth plugin or user-agent spoofing
- **Heavy sites may be slow**: Implement viewport-only rendering, skip off-screen content
- **File uploads in browsed sites**: Not supported in initial version
- **Authentication in browsed sites**: Cookies persist within session only

## Summary

This plan introduces a server-side Puppeteer-based browser that enables:
1. **Full website navigation** without cross-origin restrictions
2. **Native screenshot capture** with timestamp and URL metadata
3. **Positional annotations** on screenshots with a familiar pin-based UI

The architecture leverages the existing Socket.io infrastructure for real-time browser control while adding new database models and API routes for screenshot/annotation persistence.
