# Mobile Viewport Toggle for MiniBrowser

## Overview

Add viewport simulation capabilities to the MiniBrowser component, allowing users to toggle between desktop and mobile views when previewing websites. This enables collecting UI feedback on how applications appear on different device sizes.

## Tech Stack

| Layer | Technology | Rationale |
|-------|------------|-----------|
| UI Components | React + TypeScript | Existing stack |
| Styling | Tailwind CSS | Consistent with current patterns |
| State | React useState | Local component state is sufficient |
| Icons | Inline SVG | Matches existing toolbar icons |

## Features

### 1. Viewport Preset System
- **Description**: Define common device viewport sizes (desktop, tablet, mobile)
- **Components**: New `viewportPresets` constant with device dimensions
- **Files**: [MiniBrowser.tsx](src/components/MiniBrowser.tsx)

### 2. Viewport Toggle UI
- **Description**: Add a dropdown/button group in the toolbar to switch viewports
- **Components**: Toggle buttons with device icons (desktop, tablet, phone)
- **Files**: [MiniBrowser.tsx](src/components/MiniBrowser.tsx)

### 3. Responsive Iframe Container
- **Description**: Constrain iframe dimensions based on selected viewport
- **Components**: Modified viewport container with dynamic sizing and centering
- **Files**: [MiniBrowser.tsx](src/components/MiniBrowser.tsx)

### 4. Device Frame (Optional Enhancement)
- **Description**: Visual device frame around mobile/tablet viewports for context
- **Components**: CSS-based device chrome styling
- **Files**: [MiniBrowser.tsx](src/components/MiniBrowser.tsx)

## Data Schema

No database changes required. Viewport state is local to the MiniBrowser component.

```typescript
// Viewport preset type
interface ViewportPreset {
  id: string;
  name: string;
  width: number | null;  // null = responsive/full width
  height: number | null; // null = responsive/full height
  icon: 'desktop' | 'tablet' | 'phone';
}

// Presets
const VIEWPORT_PRESETS: ViewportPreset[] = [
  { id: 'desktop', name: 'Desktop', width: null, height: null, icon: 'desktop' },
  { id: 'tablet', name: 'Tablet', width: 768, height: 1024, icon: 'tablet' },
  { id: 'mobile', name: 'Mobile', width: 375, height: 667, icon: 'phone' },
  { id: 'mobile-lg', name: 'Mobile Large', width: 428, height: 926, icon: 'phone' },
];
```

## Implementation Steps

### Phase 1: Core Viewport Toggle

1. **Add viewport presets constant**
   - Define `VIEWPORT_PRESETS` array with desktop, tablet, and mobile sizes
   - Include common device dimensions (iPhone, iPad, etc.)

2. **Add viewport state to MiniBrowser**
   - Add `useState` for current viewport preset
   - Default to 'desktop' (full width/height)

3. **Create viewport toggle buttons**
   - Add button group after reload button in toolbar
   - Three buttons: Desktop, Tablet, Mobile
   - Use SVG icons matching existing toolbar style
   - Highlight active viewport

4. **Modify iframe container styling**
   - When viewport is not 'desktop':
     - Set explicit width/height on iframe container
     - Center the container horizontally and vertically
     - Add subtle background behind the container
   - When viewport is 'desktop':
     - Use current flex-1 full-size behavior

5. **Add scale-to-fit logic**
   - If selected viewport dimensions exceed available space:
     - Scale down using CSS transform
     - Maintain aspect ratio
   - Show actual dimensions in UI

### Phase 2: Enhanced UX

6. **Add viewport dropdown for more presets**
   - Click on device button shows dropdown with specific devices
   - e.g., "Mobile" expands to: iPhone SE, iPhone 15, Pixel 7

7. **Add rotate button for mobile/tablet**
   - Toggle between portrait and landscape orientations
   - Swap width/height values

8. **Persist viewport choice**
   - Save last used viewport to localStorage
   - Restore on component mount

### Phase 3: Polish

9. **Add device frame styling**
   - Optional visual frame around mobile viewport
   - Rounded corners, notch indicator for modern phones
   - Toggle to show/hide frame

10. **Update screenshot capture**
    - Ensure captured area matches viewport bounds
    - Include viewport size in screenshot metadata

## Considerations

### Technical
- **Iframe sizing**: The iframe content won't actually be responsive - we're simulating by constraining the container. Sites with CSS viewport queries may not behave exactly as on a real device.
- **Screenshot accuracy**: The `viewportRef` bounding rect will need to account for any CSS transforms applied for scaling.
- **Overflow handling**: Need `overflow: hidden` on container when viewport is smaller than available space.

### UX
- **Visual feedback**: Clear indication of current viewport mode
- **Smooth transitions**: Animate viewport changes for polish
- **Quick access**: Desktop/Mobile should be one-click actions, not buried in menus

### Future Enhancements
- Custom viewport dimensions input
- Save favorite viewport presets
- Sync viewport with actual browser DevTools
- Touch emulation hint/reminder
